# Slab run 2 — the ±RNA panel

Run 1 swept many constructs at whatever concentration each box happened to
give, **without the optimised restraints**. This is the narrow re-run: fewer
cells, replicated, one concentration, and the restraint set the Phase 2.5 sweep
actually selected.

Generated by `../../prepare_slab_rna.py`; regenerate with

```bash
python prepare_slab_rna.py --report                      # plan only
python prepare_slab_rna.py --conc 100 --seeds 3 --tier both
```

Layout is flat — `rnapanel/<construct>__<arm>__seed<N>/` — so the existing
queue treats the whole panel as one "arm":

```bash
GPU=2 ./run_slab_queue.sh rnapanel        # or ./run_rnapanel_gpu2.sh
python monitor_slab.py --watch
```

## The question

Run 1 found RNA retards dispersal **1.67×, but only when ART is present**. That
is one number from one unreplicated cell, on a construct whose KH domains were
not bridged. This panel asks whether it survives replication and correct
restraints, and where along the domain architecture the effect enters.

Each × 2 arms (`homotypic`, `rna`) × 3 seeds (12345 / 23456 / 34567).
**24 runs queued, 18 parked.** ~11.5 GPU-days for the core tier.

`core` is KH7a + MD1 + MD2 + MD3 + KHb–KH8 + WWE + ART (FL 738–1801, 1064 aa).

The three `_khb` constructs truncate at KHb–KH8, removing **both** WWE and ART.
They are the direct test of whether the RNA/ART coupling needs ART
specifically, rather than just a shorter chain. Parked at staging; `rm .parked`
to queue them.

`md_full` carries no KH domain, so it gets no bridge and — in run 1 — was the
one construct that formed a condensate at all (liquid at 108 mM, jammed at
406 mM). It is the positive control here.

## What changed from run 1

1. **Optimised restraints.** Per-domain trims from the Phase 2.5 sweep plus the
   141-pair KH7a–KHb bridge at k=350. Run 1 had neither.
2. **One concentration.** Every cell at 100 mM residues (±0.1), so ±RNA and
   across-construct differences are not confounded with density. Run 1 spanned
   108–431 mM.
3. **n=3, seeds paired across arms.** `homotypic` and `rna` share seeds, so the
   comparison is matched rather than between independent draws.
4. **`checkpoint_interval = wfreq`** (100k steps), so a leg killed by GPU
   contention loses ≤1 frame instead of a whole batch.
5. **RNA at 0.30 chains of polyU40 per protein**, the same ratio as run 1.

## Three bugs found while validating this panel

Each would have silently invalidated the comparison:

* **The RNA force field was falling back to CALVADOS package defaults.**
  `prepare_slab.py` sets `RNA_OPTS` explicitly (kb 1400/2200, ka 4.20, nb
  cutoff 2.0); the package defaults are much stiffer (8033/8033, 7.24, 0.6).
  Omitting them substitutes a different polymer, so the +RNA arm would not have
  been comparable to run 1 at all.

* **Custom restraints are per chain copy and are NOT broadcast.** The file
  format is `name copy bead | name copy bead | r k`, and
  `Sim.map_custom_restraints` resolves each line to exactly one bead pair via
  `start_bead + (copy-1)*nbeads + (bead-1)`. Every monomer run had `nmol=1`, so
  emitting only `copy 1` was always correct — and here it would have bridged
  1 chain of 47. Now expanded per copy: 141 × nchain, confirmed in the build
  logs (`Number of custom restraints: 6627` for core_full_go's 47 chains).

* **`map_custom_restraints` printed every restraint unguarded** — ~9k lines /
  600 kB per build, reprinted on every leg restart. Removed upstream
  (`calvados/sim.py`, backup at `sim.py.bak_cresprint`).

## Validation

`fl`, `core_full_go` (KH bridge + RNA), `md_full` (RNA, no bridge) and
`core_khb` all build and run 200 steps on CUDA (L40S). Restraint counts, RNA
chain counts and the absence of a bridge in `md_full` were checked in the
build logs.
